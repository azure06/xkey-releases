# How updates work

[日本語](/ja/updates)

## Standalone

The bundled updater checks GitHub when PowerPoint starts, at most once every six hours per Windows user and update channel. Restarting PowerPoint immediately after a check does not force another check.

When an update is offered:

1. Accept the offer and leave the updater window open.
2. Save your presentations and close **all** PowerPoint windows.
3. Approve the Windows administrator prompt.
4. Wait for installation to finish, then reopen PowerPoint.

The updater checks the download's identity, signature and hash before installation. It does not force PowerPoint to close. **Postpone cancels the current attempt**; it does not arrange an unattended installation later. Cancelling approval or a failed download leaves the existing installation in place.

### Check manually

Run this command in PowerShell to request an immediate update check:

```powershell
& 'C:\Program Files\Infiniti XKey for PowerPoint\Updater\XKey.Updater.exe' --update
```

This bypasses the six-hour timer but still respects GitHub rate limits. `--status` reports the updater's activation and channel; `--check` checks availability without downloading.

### Stable and Preview

New installations default to **Stable**, which follows GitHub's Latest published full release. **Preview** also considers prereleases and selects the highest published valid version. Only newer versions are offered; equal versions and downgrades are skipped.

Preview is an administrator-controlled testing option. See the package's `runtime-configuration.md` for configuration. The update channel does not change the application's backend or sign-in environment.

If the selected channel has no eligible newer version, there is no update to install. Network failures and rate limits do not remove the installed app.

## Intune

The Intune distribution has no self-updater. IT downloads a new package, tests it and deploys it through the company's management process. Publishing a package on GitHub does not update Intune assignments automatically. See [Corporate deployment](/enterprise).

## ClickOnce

ClickOnce uses the update settings and installation URL of its original deployment. The Standalone helper and its Stable/Preview selection do not control ClickOnce updates.

## Diagnostics

User-side updater log: `%LOCALAPPDATA%\Infiniti\XKey\Updates\updater.log`.

Protected installation logs: `%ProgramData%\Infiniti\XKey\Updates\<job>\install.log` and `result.txt`. Ask an administrator to inspect them if installation does not complete. Review logs for private information before sharing them.
